# 07 文件保存规范

## 1. 落位速查

| 要保存的东西 | 位置 | 命名 |
|---|---|---|
| 引擎/服务/工具代码 | `core/` 对应子包 | 英文 snake_case `.py` |
| 新机制模块 | `core/engine/` | 单一职责一名一文件（如 `quest.py`） |
| 测试 | `tests/` | `test_<主题>.py` |
| 静态数据 | `assets/` 对应子目录 | 见数据规范 |
| 试玩/维护脚本 | `tools/`（试玩进 `tools/playtest_kit/`） | 动词开头（`run_*`、`build_*`、`split_*`） |
| 构建产物/脚本 | `build/` | `build_windows.bat`、`FateEngine.spec` |
| 历史设计文档 | `docs/` | 中文名可，头部必须带「⚠️ 历史文档」标注 |
| 规范文档 | `standards/` | `NN-主题.md` 两位数字前缀排序 |
| 运行数据 | `var/`（程序自动建，勿手建） | 见数据规范 |

**禁止**：项目根新增 `.py` 模块、根目录新增数据目录、根目录新增说明文档（README.md 是唯一用户文档）、`__pycache__`/临时文件入库。

## 2. 编码与格式

- 全部文本文件 **UTF-8 无 BOM**；Python 源文件头 `# -*- coding: utf-8 -*-`。
- 换行：LF（Windows 上编辑器保持 LF，勿让 CRLF 混入库）。
- Markdown：中文正文 + 半角标点用于代码/命令；文档内引用的路径必须是当前真实路径（改了结构就更新文档）。
- JSON：`ensure_ascii=False`、两空格缩进、尾换行。

## 3. 命名

- Python 模块/包：英文小写蛇形（`anchor_distiller.py`）；类：大驼峰；函数/变量：蛇形；常量：大写蛇形。
- 数据文件：角色卡/名册等 JSON 用稳定 id（`<id>.json`），用户卡 `user-` 前缀；切章 `NNNN.txt`（4 位数字）；锚点 `NNNN.json`。
- 日志/会话目录：`session_<时间戳>.md`、`sessions/<时间戳>/`。
- 禁止中文文件名用于代码与构建产物（数据内容里的中文不受限）。

## 4. 写入纪律

- 写文件**先写临时文件再原子替换**（`xxx.json.tmp` → `replace`，anchor_distiller 与 persistence 先例），防止半写状态。
- 落盘前脱敏：API Key、token 类字段在写入 state/存档/日志/会话前必须移除（`redact_secrets`、`_without_secrets`）。
- 大文件（>10MB）不入库；书库切章产物只在 var/。
- 备份类文件（`*.bak`）只保留一份最新的，历史副本及时清理。

## 5. 清理纪律

- `__pycache__`、`.pyc` 是缓存，随时可删，不得作为交付内容。
- 删除文件/目录前必须完成引用检查（见 06 规范）；删不掉的（环境回收站策略拦截）必须在交付说明中列为"待手动清理"清单。
- 移动目录时警惕**嵌套事故**：目标目录已存在时 `mv` 会把源嵌进去（本项目实测翻车）——移动前先确认目标不存在，或复制后校验再删源。
- 每个改动阶段结束清理自己产生的临时文件（/tmp 备份、*.tmp）。
