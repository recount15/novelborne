# 书中织梦 · Novelborne

Novelborne 是一个由大模型驱动的互动小说世界模拟器。玩家以穿越者身份进入原著世界，模型负责呈现角色与场景，程序负责世界规则、锚点、涟漪、任务、角色状态、收束力和会话持久化。

> 这不是让模型一次性“写完一回合”的聊天壳，而是“结构化出卷 → 并行填空 → 空级批改 → 错题重填 → 代码组装 → 全局润色 → 机制结算”的叙事运行时。

## 项目定位

Novelborne 的核心目标是把大模型的不确定性限制在小的、可验证的生成任务中：

- AI 填写结构化剧情蓝图、角色节拍、分段正文、选项和角色状态补丁；
- 代码负责档位、角色名册、锚点、任务、碎锚、涟漪、收束力、金手指冷却与状态事务；
- 只有最终文字整合阶段负责把结构化答卷还原为自然、连续、无明显代码痕迹的小说正文。

## 主要能力

### 强化模式（主推）

强化模式需要上传可切章的完整 TXT 原著，适合长期运行和高还原度模拟：

- 开局并行蒸馏剧情摘要、作品档案、首批锚点和角色卡；
- 首章锚点使用二次核验，长章节使用分块合并，角色卡通过质量门后进入角色库；
- 角色、伴侣、伙伴、宿敌和角色关系状态参与每回合生成；
- 原著锚点、涟漪等级、相容性 K、动态收束力和碎锚任务共同影响剧情；
- 任务目标和碎锚阶段会进入蓝图、段落答卷和全局后处理，不再只在回合末被动判定；
- 6 档剧情丰度可选，最高档必须开启类 Agent 生成；
- 通过全局并发控制器和锚点 worker 池换取更短等待时间。

### 普通模式

普通模式从作品库选择作品档案，保留较轻量的 legacy 生成体验，只开放前两档剧情丰度，不启用强化模式的完整角色与锚点运行链。

## 六档剧情丰度

| 档位 | 目标规模 | 普通模式 | 类 Agent |
|---|---:|:---:|:---:|
| 1 轻盈 | 约 400 字 | ✓ | 可选 |
| 2 简明 | 约 650 字 | ✓ | 可选 |
| 3 标准 | 约 950 字 | — | 可选 |
| 4 丰厚 | 约 1350 字 | — | 可选 |
| 5 鸿篇 | 约 1850 字 | — | 建议开启 |
| 6 史诗 | 约 2400 字 | — | **必须开启** |

“剧情丰度”表示每回合的场景展开程度，不是模型的硬性字数承诺。内部通过同族结构化槽位和分段窗口控制内容密度；失败时只重填具体不合格空，不把整个回合打回重写。

## 结构化生成与门禁

### 空级质量检测

质量检查下沉到生成空：

- 段落空：窗口、必含词、角色点名、互动、禁用词；
- 锚点空：证据词、动作、结果、因果和否定窗口；
- 选项空：6 条、A–F、4 金手指 + 2 性格、预告和去重；
- 角色状态空：角色名、正文证据子串、关系变化和摘要；
- 任务/碎锚空：目标或阶段要求的可观察推进。

整回合只保留格式检查：JSON、代码围栏、系统校验段、隐藏日志和选项列表不得混入正文。最终答卷的自然度由无门禁的流程化后处理负责；后处理失败安全回退到初步组装稿。

## 角色与锚点

- 角色卡包含目标、恐惧、能力、关系倾向、认知范围、语言风格和不可接受行为；
- 每回合根据相关度、参与度、关系状态和冷却选择在场角色；
- 角色状态补丁只有在证据逐字出现在最终正文中时才入账；
- 锚点包含章节、标题、摘要、事件、角色、世界、伏笔、原文引文和涟漪；
- 锚点引文必须逐字命中原文，模型失败时可使用原文摘录式确定性兜底；
- 开局蒸馏默认优先当前章和近邻章节，后台继续前瞻蒸馏；
- 永久通路作弊码会触发全局碎锚，三愿和永久增补会进入结构化铁律账本。

## 并发策略

进程级 API 动态并发控制器具备硬上限 10：

- 默认目标并发 6；
- 开局蒸馏优先于回合生成，回合生成优先于后台前瞻蒸馏；
- 限流或超时会自动降低并发并在冷却后恢复；
- 达不到目标并发时任务排队，不把“并发不足”当成业务错误；
- 同一波作业保持扁平提交，避免线程池嵌套死锁。

## 快速开始

需要 Python 3.10+、Node.js 18+：

```bash
pip install -r requirements.txt
cd frontend
npm install
npm run build
cd ..
python run_app.py
```

浏览器访问：<http://127.0.0.1:8000>

首次运行后，在页面中配置 OpenAI 兼容服务的 API Key、模型、模式、原著和角色。API Key 只在当前页面和服务端进程内存中使用，不写入存档、日志、数据库或发布包。

## 局域网与二维码

默认启动监听 `0.0.0.0`，同一 Wi-Fi 下的手机可以访问。点击顶栏手机图标后，系统会：

1. 枚举可用局域网 IPv4 地址；
2. 为每个网卡提供独立访问地址；
3. 生成包含当前会话 ID 的二维码；
4. 允许在多个网卡地址之间切换。

如果手机无法访问：

- 确认电脑和手机连接同一 Wi-Fi；
- 不要使用 `--host 127.0.0.1` 或窗口版的 `--no-lan`；
- 在 Windows 防火墙中允许程序或放行对应端口；
- 多网卡环境下在二维码窗口切换到实际 Wi-Fi 地址。

示例：

```bash
python run_app.py --host 0.0.0.0 --port 8000
python run_app.py --host 127.0.0.1 --port 8000  # 仅本机
```

二维码中的 `session` 参数使用服务端原始会话 ID，扫码后会恢复同一局面，而不是创建新会话。

## Windows 构建

先完成前端构建，再安装 PyInstaller：

```bash
pip install pyinstaller pywebview pythonnet clr-loader
build\build_windows.bat
build\build_windows_windowed.bat
```

产物：

- `dist\FateEngine\FateEngine.exe`：Web 版；
- `dist\FateEngineWindowed\FateEngineWindowed.exe`：窗口版。

发布时必须分发整个目录，不能只复制 EXE。运行数据由程序在 EXE 同级 `var/` 自动创建。
