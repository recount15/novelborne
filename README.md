# 书中织梦 · Novelborne（原 fate-engine）

> 你扮演**穿越者**，AI 扮演**命运引擎**——忠实还原原著世界，让穿越者拥有真实选择权。原著大事尽量发生；你的原创事件可以留下，影响越大越需要积势与代价，不会用橡皮筋把世界强行拉回去。

一个基于大模型的「小说世界模拟」交互程序：作品库内置原创示例、支持上传 TXT 原著快速蒸馏收录（同步提取角色性格卡入角色库），配一整套确定性规则代码，支持 DeepSeek、通义千问、Kimi、智谱、OpenAI 及自定义 OpenAI 兼容服务。

## 一、快速开始

### 从源码运行（推荐）

需要 Python 3.10+ 与 Node.js 18+：

```bash
pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..
python run_app.py
```

程序启动后自动打开 `http://127.0.0.1:8000`：前端页面与 `/api` 接口在同一端口，**一个进程即是全部**。在左侧连接模型服务（填 API Key 或配置环境变量），选择作品与角色，即可开局。

**手机远程使用（局域网）**：默认监听 `0.0.0.0`，手机与电脑连同一 Wi-Fi 后，点顶栏手机图标扫码（或输入启动横幅打印的局域网地址）即可在手机上游玩；仅本机使用可加 `--host 127.0.0.1`。首次访问可能需在 Windows 防火墙放行 Python。

**多实例并行**：同一台机器可同时运行多份程序——`python run_app.py --port 8010 --var var/cluster/a --no-browser` 指定独立端口与数据目录（config、存档、会话、上传、日志、SQLite 全部隔离），适合集群测试或多人共用一台机器。

开发调试可用 Vite 热更新：另开终端 `cd frontend && npm run dev`（:5173，自动代理 `/api` 到 :8000）。

### Windows 可执行版

获取完整的 `dist\FateEngine` 文件夹（不能只复制 EXE），双击 `FateEngine.exe` 即可，目标电脑无需安装 Python/Node.js。自行构建见第五节。

> API Key 只在当前页面与服务端进程内存中使用，不写入配置、存档、会话记录或日志。

## 二、两种模式

| | 基础模式 | 强化模式 |
| --- | --- | --- |
| 原著来源 | 从作品库选择档案（内置原创示例 + 上传蒸馏收录的书目） | 上传可成功切章的完整 TXT 原著 |
| 推进范围 | 指定具体片段，10–30 回合内收束 | 从故事开篇起，按章节预算持续推进 |
| 人物机制 | 不启用 | 伙伴/伴侣/宿敌三类机制、名册、阵营势差 |
| 存档 | 不提供跨片段存档 | 存档、工作记录与运行日志 |

边界由代码强制：强化模式切章校验不通过时前后端都禁止开局；基础模式的人物机制配置一律被忽略。

## 三、核心机制

- **原著锚点**：主线大事「尽力发生」——你改变的是路径、代价与见证者，不是凭空删除剧情；每章按字符数计算回合预算（turn_budget）。
- **涟漪 L0–L4 与积势**：每个行动留下涟漪；L0–L2 原创行动真实留存，L3–L4 大改动必须多回合积势并通过相容性 K（≥60）校验，不足则转为旁支、代价或未遂。
- **收束力三档**：一般 / 较高 / 极高——越高剧情越贴主线、偏离越容易被世界拉回；确认设定后锁定。
- **金手指**：有作用域、代价与冷却，强度与世界难度挂钩（`E = WS × GF(D)`）；自定义金手指需经提案与确认流程。
- **人物机制**：伙伴 、伴侣 、宿敌 ，各自独立建卡记账；宿敌强度由阵营势差非线性计算（成员五档 × 作用域 × 常驻度，边际递减聚合）。
- **碎锚（全局）**：积势攒满后可尝试碎锚——成功即该章及之后的**主线锚点全部失效**（剧情不再收束，此后由过往回合、角色性格与全局世界观自由生成，锚点与档案仅供参考），并同步停止后续锚点蒸馏；有失败风险与代价。某作弊码（RELAY 永久通路）确认接通时立即触发同等碎锚效果。
- **快速蒸馏入库**：强化模式上传 TXT 完成切章与剧情提取后，自动把该书的作品档案（题材/锚点/核心角色/结构化摘要）收录进基础模式作品库（W 编号自增、同名覆盖），并提取主要角色性格卡（含四维标签）入角色库；另有 `POST /api/books/quick-distill` 手动复蒸入口。
- **穿越身份落定（代码级）**：卡和性格都只是「魂」，名字（穿成谁）开局时由模型确定——主角留空默认穿成原著主角，伴侣/伙伴/宿敌留空默认穿成性格最类似（或最贴合定位）的原著角色；分配结果经代码校验后锁定，开局回执展示「穿越对照表」（实际名字+身份+身体性别），本局不得更改。附身不受性别限制，叙事以附身角色的生理性别为准；唯一硬性要求是禁止悬空穿越。
- **九风格与桥段库**：行动型/谋略型/苟稳型/规则型/义守型/乐趣型/探索型/情感型/成长型，检索通用桥段模板实例化。
- **长局自维护**：每 5 回合生成人物近况摘要；每 10 回合评价 + 压缩对话历史，token 消耗不随回合数无限增长。
- **刷新不丢档**：会话自动落盘，刷新页面或重启服务后自动恢复聊天与开局设定（API Key 不落盘，恢复后重填即可）。
- **锚点蒸馏容错**：模型输出的形式问题（空项、超长项、章号错位、改写引文）由形式修正层自动修复；失败自动退避重试，右侧进度窗实时可见。
- **固定 6+1 选项**：每回合 6 个可选行动 + 1 个自由输入，程序逐回合解析校验。

开局前聊天界面会展示一份「玩法速览」，右侧状态面板实时可见涟漪、积势、宿敌动向、任务与锚点蒸馏进度。

## 四、项目结构

```
novelborne/
├── run_app.py          # 唯一入口：启动服务 + 打开浏览器
├── requirements.txt
├── core/               # 全部引擎代码（分层与数据流详见 docs/ARCHITECTURE.md）
│   ├── server.py       # FastAPI 路由层（薄编排）
│   ├── app.py          # 对局编排（on_start/on_send）
│   ├── services/       # 服务层（注册表/问答/开局装配，重构渐进沉淀）
│   ├── state_schema.py # 回合事务键与设定读取的单一来源
│   ├── fate_engine.py  # 模型接入门面
│   ├── engine/         # 机制层（涟漪/锚点/名册/金手指/蒸馏等，惰性加载）
│   ├── api/            # 流式契约与会话管理
│   ├── ui/             # 展示辅助模块
│   ├── lore/           # 动态世界书
│   ├── memory/         # 结构化状态记忆
│   └── prompts/        # 提示词加载器
├── assets/             # 全部静态数据
│   ├── rules/          # 运行时规则与作品库（原创示例 + 上传蒸馏条目）
│   ├── data/           # 角色卡、桥段库、技能目录等 JSON（含 samples/ 原创样书）
│   ├── personas/       # 性格模型目录（standard / enhanced；当前为空，可自行扩充）
│   ├── prompts/        # 提示词文案
│   └── lore/           # 默认世界书
├── var/                # 全部运行数据（程序自动创建，勿提交）
│   ├── db/ books/ saves/ sessions/ logs/ outputs/ uploads/
├── docs/               # 架构地图 / 接手手册 / 文档规范
├── tools/              # 试玩流水线与维护脚本
├── scripts/            # 一次性数据迁移脚本（历史 data/ 布局时代产物）
├── build/              # exe 构建脚本与 PyInstaller spec（产物在根 dist\）
├── frontend/           # Vue 3 + TypeScript + Tailwind 前端
└── standards/          # 项目规范（AI 协作宪法：架构/代码/数据/接口/测试/提交/文件）
```

## 五、构建可执行版

```bat
build\build_windows.bat
```

产物在 `dist\FateEngine\`（含 Python 运行时、assets、前端），整个文件夹拷贝分发即可；运行数据由程序在 exe 同级 `var/` 下自动创建。
