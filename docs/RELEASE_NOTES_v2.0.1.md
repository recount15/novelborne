# v2.0.1 Release Notes

### 局域网与二维码

- 修复二维码将无连字符 session ID 改写成带连字符 UUID、导致手机端恢复会话 404 的问题；二维码现在保留服务端原始会话 ID。
- 局域网地址不再只使用默认路由：同时枚举可用 IPv4，并优先展示 RFC1918 私网地址。
- 多网卡环境可以在二维码弹窗中切换 Wi-Fi/以太网地址；二维码端点只接受服务端枚举的地址。
- 新增局域网信息、二维码 PNG、原 session 接续和 frozen 数据路径回归测试。

## 主要更新

### 强化模式：剧情丰度填空生成

- 强化模式默认启用 `compose_mode`：导演卷生成结构化蓝图，多个段卷与选项卷并行填空。
- 剧情丰度改为双族六档：轻盈、简明、标准、丰厚、鸿篇、史诗。内部通过结构化填空模板实现，用户只需选择丰度档位。
- 普通模式开放前两档；史诗档强制开启类 Agent。
- API 动态并发控制器硬上限 10，自动限流退避；并发不足时排队，不因并发目标不可达而失败。

### 空级批改与全局后处理

- 体量、角色、锚点、任务与选项等质量检查下沉到各填空项；只重填不合格答卷。
- 整回合只保留 JSON、代码围栏、系统标记、隐藏日志和选项块等格式检查。
- 新增全局答卷整合润色：按事实锁定、接缝整合、文学润色、输出整理四步，把分段答卷化零为整。
- 全局后处理覆盖锚点、角色、金手指、涟漪、任务、碎锚、宿敌、玩家铁律、记忆与悬念；失败时安全回退初步组装稿，不阻断回合。

### 锚点与开局蒸馏

- 开局剧情、角色和首章锚点并行蒸馏；长章节使用 map-reduce 全文覆盖。
- 首章锚点两遍核验；角色卡通过质量门后才入库。
- 锚点蒸馏改为 worker 池，退避重试不阻塞其他章节。
- 当前章锚点缺失时自动救援；模型失败可使用原文摘录式锚点放行并后台精化。

### 角色、任务与碎锚

- 在场角色按角色卡生成逐回合 beat contract。
- 新增角色状态 patch：关系变化必须有最终正文中的逐字证据，校验后写入状态记忆。
- 任务目标和碎锚阶段要求进入蓝图、段卷和全局后处理，不再只在结算阶段被动判定。

### 三愿与永久增补通路

- 三愿和永久增补改为结构化铁律账本。
- 铁律按当前锚点、在场角色、地点与世界书命中选择注入；未命中不再全量占用 system prompt。
- 支持铁律取代、旧存档幂等迁移，保留前端与旧字段兼容。
