## 0. 目标、承诺边界与执行纪律

目标：让不熟悉项目、推理能力有限的执行者，依据明确步骤完成已知缺陷修正、全功能盘点、自动回归、12实例并行、真实内容生成与GUI验收，并留下可复核证据。

“全量”定义：以本次冻结的源码路由、运行时OpenAPI、前端实际入口及用户手册建立功能清单，每项均有结论。不是只把现有测试跑绿，也不是用一次开局代表整个功能。
“完整可用”定义：指定版本、Windows环境、浏览器、模式、数据规模和内容生产路径内，全部必测场景通过，阻断问题清零。有限测试不能保证所有未来输入、所有外部模型及所有环境永无故障。未测项不得写成可用。

统一规则：
1. 一次只执行一个有编号的任务卡。先检查前置，再实施，再运行本卡验证，再保存证据。没有前置证据不得跳步。
2. PASS=全部预期成立；FAIL=执行后不符合预期；BLOCKED=前置不成立；NOT_RUN=未执行；N/A=确实不适用且有书面理由。禁止将BLOCKED/N/A计入通过数。
3. 每个缺陷修正必须先有能复现该缺陷的失败回归，再作最小修正，再运行针对性及全量回归。不要为通过测试修改公共白名单、删除断言、吞异常、伪造状态或替换真实功能。
4. 同一确定性用例最多修正重跑3轮。3轮后仍失败，记录阻断并停止依赖链；其他独立模块可继续。不无限重试，不擅自改变需求。
5. 网络瞬时错误与业务失败分别记录。只对明确可重试的网络错误有限退避；鉴权失败、源指纹变化、协议错误不得盲目重试。
6. 原始失败记录不可覆盖。修复后追加新结果，用缺陷ID关联。
7. “HTTP 200”“有session_id”“有输出文字”“离线校验通过”“进度100%”均不单独构成业务成功。
8. 执行者不得依据本文的预期编造实际结果。时间、耗时、通过数、任务状态一律取本轮事实。

## 3. 目录、证据与交接格式

创建唯一RUN_ID：本机时间YYYYMMDD_HHMMSS加8位随机值。禁止复用旧RUN_ID。
本轮根目录：<repo>\var\acceptance\<RUN_ID>。
下文<repo>始终指开发目录；所有尖括号是待执行者从manifest读取的实际值，不可原样执行。

必须建立：
- manifest.json：run_id、环境版本、代码文件SHA256清单、语料SHA256、允许目录、禁止目录、分配端口、模型路径、测试范围、脱敏规则版本。
- processes.jsonl：每次启动/停止逐条追加PID、create_time、argv、cwd、instance_id、var目录、退出码。
- coverage.json：功能清单及每个用例的状态。
- defects.jsonl：缺陷ID、严重度、归因、复现、预期、实际、证据位置、影响用例、修复文件、回归结果。
- cases/<CASE_ID>/<attempt>/result.json：开始结束时间、输入摘要、步骤、每步断言、结论、代码哈希、证据索引。
- instances/L01…L12/：每实例独立var与testlog。
- queue/<run_id>/<lane_id>/：pending/running/done/failed/cancelled；任务标识必须是完整ID。
- private-evidence/：必要的正文、响应与截图，仅本地。
- report/：脱敏最终报告、功能覆盖表、质量报告、停止与清理报告。

日志统一字段：run_id、lane_id、case_id、attempt、request_id、task_id、时间、事件类型。每条append后flush；异常和退出也必须落盘。
HTTP日志不记录凭据；默认只记路由模板、状态、耗时和脱敏摘要。模型正文如确需保留，放private-evidence，不写进可分享报告。

执行交接必须输出：最后完成任务卡；当前卡与失败步骤；仍运行的己方PID；队列未结任务；下一条确定操作；禁止操作。不得只写“继续测试”。

### B02 任务等待与日志
操作：集中枚举READY/FAILED/CANCELLED/INTERRUPTED；超时单独为TIMEOUT测试结论而非伪造服务终态。任何异常均在finally输出summary。报告区分主失败和依赖BLOCKED；质量发现参与最终门禁。
断言：注入四类终态均及时返回；进程被停止仍有末次进度；重复质量告警归为同缺陷并保留发生次数；没有evidence路径为空的已确认缺陷。

### B03 并行隔离与进程管理
操作：run_id/instance_id/queue namespace贯穿请求与任务；记录create_time；显式环回绑定；拒绝己方启动失败后误连旧服务；停止消费者后再关闭任务和实例。
验证：两个独立实例同名会话不串状态，两个run不串队列；错误PID或创建时间时停止器拒绝杀进程；端口已占用时启动失败且不接管旧服务。

### B04 真实应答与缓存分离
建立三种模式并写入每条结果：
- deterministic：合成错误输入/固定回答，仅测协议、恢复和回归。
- zcode-live：当前任务由ZCode委派重新生成，用于本次真实内容生产验收。
- replay：复用已验证回答，仅用于可重复回归，不计实时生成、语义质量或模型性能成绩。

每个真实任务必须带完整消息、当前配置、运行/实例/用例ID、源全文SHA256、schema版本、完整任务ID。不得仅依赖前120字符匹配。
应答流程：领取 -> 核对身份/源指纹 -> 阅读全部当前消息 -> 产答 -> 完整validator预检 -> 失败原样记录并据反馈修正 -> 再校验 -> 提交 -> 核对桥消费确认和应用业务结果。
禁止固定给所有角色分配杨明、固定能力数值、跨块引文、改变原文引号、为了通过删除实体。模型前置校验通过不算最终用例通过。
如任务含不适宜生成内容，只提供非露骨、非色情的情节概述与中性功能测试内容；不得为覆盖率生成不允许内容，该内容分支如无法安全验证必须标记范围限制。

### B05 编排与覆盖台账
实现真正phase2，不再用占位返回代表完成；支持12独立实例、每lane上限、全局上限、停止开关、失败归档、finally回收。

统计同时报告应用活跃实例数、HTTP在途数、模型生成在途数、队列等待时间和处理时间。12实例不等于12模型并行。
B门禁：新增测试器自测全部通过；故意注入的失败不会被判PASS；未启动用户实例；不存在共享目录/错误归属。
