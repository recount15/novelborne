# 剧情、任务、阅读器与三愿码统一施工及验收计划

版本：1.0｜2026-09-10
状态：设计文档；未实施，未运行验收。用户停止的试验保持停止。

## 0. 目标、范围与不可违反的边界

目标：以原著为基础，以明确授权的三愿码和玩家行为形成合理分歧；剧情、任务、阅读器共享事实来源，但不混淆原著与本局。低能力执行智能体能按卡施工；低能力运行模型不能因软质量门禁陷入无限重试。

仅修改 C:\Novelborne\Novelborne-state-refactor。原源码、便携版、恢复包及用户数据为回退资产。不得改动或重启用户 21560 实例。源码、角色、原书、数据库、日志及私有构建不上传。不得找回旧凭据。后续测试只能使用有清单、独立目录的实例；停止进程须核对 PID、命令、目录和创建时间，不得按端口杀进程。

本计划不执行重写全引擎、不替换数据库权威、不变更公开资产白名单、不删除旧验收记录、不以扩大超时或手工代写答案证明真实生成质量。

本计划优先于旧验收计划中冲突的剧情质量判据；旧文档中的隔离、事务、安全、原文引用、正式 A–F 选项协议等要求继续有效。不得覆盖旧计划和旧结果。

### 两类“低能力”必须分别解决

1. 施工智能体：通过小变更卡、确定字段、现有入口、反例和退出条件减少自由发挥。
2. 运行模型：通过结构化系统上下文、确定性修复、短输出契约、总预算与可恢复失败避免死锁。

非死锁不等于任何模型都保证生成合格正文；意味着每个请求在有限时间内结束，状态正确，用户可继续操作。

## 2. 统一事实与授权契约

复用现有状态和快照，不新增平行权威存储。以下是逻辑字段要求；施工卡 C01 必须给出与现有字段的准确映射后，后续卡才能编码。

### 2.1 事实记录

必需字段：id、kind、text、scope、evidence_refs、status；必要时附 authorized_by、committed_event_id、known_by、supersedes。

kind：
- canon：有书籍标识、原文 hash、章/范围及证据引用的原著事实。
- authorized：用户已确认的愿望/开局配置；授权子类型必须区分 wish、opening、golden_finger。
- event：成功提交的本局事件，绑定事件 ID 与 revision。
- hypothesis：人物猜测、未确认推断。
- decoration：普通描写，不授予世界规则效力。
- unknown_legacy：旧数据无法确定来源，不伪造历史授权或证据。

scope 至少区分 book/source、session/branch。事实成立与角色知道该事实是两个独立维度。阅读进度不得直接扩张 NPC 知识。

禁止规则：重复出现不升级来源；摘要不把猜测变事实；导出不将剧情加工结果反写权威事实；模型声明“有证据”不能替代服务器解析引用。

### 2.2 三愿码授权记录

保存 authorization_id、request_id、raw_text、accepted_interpretation、target_ids、unresolved_target_text、scope、explicit_limits、status、effect_refs、receipt、schema_version。

- 授权者是玩家，解析器可以是模型或回退规则，两者不可混淆。
- 原文没有不等于无效；只要落在有效授权范围内，允许覆盖本局相应原著结果。
- 不得自动增添代价、失效条件、幕后组织、血统或敌人。
- 已确认愿望不逐轮重新审批，不在摘要或存读档后失效。
- 无法解析对象时不扩大为全世界；保留原话和未解析对象。只有原愿望明确全局才授予全局范围。
- 明确愿望可降级为原话约束；涉及重大范围歧义时一次返回 needs_clarification，不提交效果、不扣次数、不持锁等待用户。
- 独立愿望即便对象相同也共存。相互冲突时要求明确替换/解释，不因“后出现”静默删除前者。
- 授权登记、效果、次数扣除、回执必须在同一权威提交中完成；重复请求不得重复扣费。

### 2.3 场景卡与任务记录

SceneCard：source_ref、current_objective、participants、character_motives、prerequisites、event_states、authorized_deviations、player_action、forbidden_early_reveals、optional_threads。

事件状态：not_started、active、completed、changed_by_player、unavailable。事件迁移必须关联已提交证据；玩家明确停留允许延缓，不以固定回合数强推章节。

TaskProjection：task_id、origin_refs、prerequisites、completion_predicates、evidence_event_ids、status、settlement_id。任务排序与权威奖励结算分离，不能新增第二套扣奖机制。

## 3. 产品行为契约

### 3.1 模式

原著跟随默认：保留当前阶段世界规则、人物动机和主要事件轨道，允许愿望及玩家行为产生的明确分歧。
有限分歧：允许关键事件改变，仍遵守未被覆盖的原著事实。
自由改编：可扩展故事，但仍受授权、安全、角色知情、事务规则约束。

实现初期先完成原著跟随与现有模式兼容；新增模式 UI 属于可后置项，不得阻断核心落地。不存在明确模式选择的旧档不静默重写历史，应显示兼容状态并从后续生成开始执行新约束。

### 3.2 回合生成

顺序：构造服务器快照 → 确定本轮场景目标 → 生成候选 → 检查/有限修复 → 原子提交 → 派生摘要与显示。

上下文排序：基础原著约束与有效授权 → 当前场景原文 → 已提交玩家分歧 → 最近互动 → 风格偏好。授权冲突通过结构化覆盖关系表达，不让模型自行选择“信原著还是信愿望”。

减少上下文而非无限追加整书；每轮只给相关证据与目标。通常只处理一个局部目标。取消每轮必须有谜团、悬念、爽点或新伏笔的强制要求。允许自然过渡与平静结束。

普通细节不要求补解释。原创支线数量可配置，初始最多 1 条活跃的非玩家主动支线；这是规划软限制，不得删除玩家明确引出的分歧或有效愿望。超限优先不再新开，不强行收束成新事实。

### 3.3 阅读器、访谈和 Copilot

- 原著视图：原文、原文引用、源锚点保持 source 域，不吸收愿望或本局剧情。
- 本局视图：显示已提交剧情及原著/愿望/玩家行为的来源标签，使用对应 session/branch。
- 对照信息：愿望改变了什么可明确解释，但不得把变化伪装成原文。
- 普通原著阅读不要求存在游戏 session。
- 原著人物访谈不读取本局愿望；本局访谈读取有效授权影响，但仍遵守人物知情边界。
- 上下文已由界面确定时直接使用，不反复询问。无法区分且存在会话时，可分别回答“原著中/本局中”。
- 阅读、搜索、翻章、查看锚点、访谈不推进剧情、任务或 NPC 知识。
- Copilot 状态修改仍走现有校验动作，回答文本不能授予愿望、完成任务或写入事实。
- 缓存键包含 view_mode、source_hash、session/branch、revision、cutoff 中适用部分；旧异步响应不得覆盖新视图。
- 源蒸馏失败时章节原文仍可阅读；该锚点标明 unavailable，允许以后手动重试。不能伪造通过准备门禁或声称锚点齐全。

### 3.4 摘要与导出

摘要保留来源、授权 ID、猜测属性及事件状态；压缩不得进行来源升级。
导出只加工已提交叙事，不新增重大事实或回写状态。支持区分忠实整理与风格润色；风格失败时保留忠实版本或明确导出失败，不能模板填充凑成功。跨章重放与重复须追溯上游切分/记录，不能只人工换句子消除检测结果。

## 4. 非死锁门禁与预算

### 4.1 三层结果

A. 确定性硬错误：来源/会话串用、证据引用不存在、失效 revision、未授权实际状态变更、重复扣愿望/奖励、事务失败、隐私泄漏。不得提交有问题状态。

B. 语义疑点：新增重要事实无明确依据、可能超出愿望、节奏可疑。先局部删除/收窄疑点，或保留为猜测；有疑点不等于必须整轮无限拒绝。不能把原著不匹配直接当授权失败。

C. 软质量：文笔、丰富程度、悬念强弱、可选支线进展等。不阻断有效回合，可带 warning 提交。明确的格式/选项协议仍按既有契约处理，不能借“软质量”放宽。

### 4.2 统一预算

新增请求级 BudgetContext 并接入现有 BudgetPolicy，不叠加第二套独立重试器。建议初始配置：
- 自动修复最多 2 次；确定性格式整理不调用模型。
- 整个剧情请求模型调用尝试总计最多 6 次，包含网络重试、校验、修复与必需子调用。
- 总时限初始 180 秒；单次实际超时不大于剩余预算。允许配置但必须有有限上界并显示配置。
- 阅读器问答采用独立较短预算，例如总计 3 次/60 秒。
- 数值是初始工程配置，不是已验证性能承诺。C01 先核算现有必要调用数；若结构无法满足，应缩减可选调用或明确调整配置，不静默超支。
- 取消、超时、预算耗尽为终态；晚到响应不得写入。provider/蒸馏/编排多层重试共享剩余次数。

请求终态：committed、committed_with_warnings、needs_clarification、failed_recoverable、cancelled。needs_clarification 不是等待中的服务器任务。

没有有效候选时保留上次已提交状态，提供重试/修改输入/返回阅读器入口；不得返回模板正文并声称已推进。硬错误候选不得作为 keep-best 结果。

### 4.3 有限回退不等于静默替代

保留 agent_cluster 现有严格失败语义。只有明示配置且具备确定性合法输入的兼容路径可降级；必须记录路径及原因。禁止缺 worker 时偷偷绕开证据验证，禁止验证器失败就允许模型自证正确。

## 5. 施工纪律与通用完成标准

每张卡：读取指定入口和现有测试 → 写能复现目标缺陷的失败测试 → 最小修改 → 目标测试 → 相关回归 → 记录结果。新功能测试必须证明旧实现不具备目标行为，不能预先写恒真断言。

每次只进行一张卡。卡内先后顺序固定。遇到需要扩大允许文件集、变更对外协议语义或降低旧硬门禁时，记录阻塞原因，不自行换架构。不可用删测试、扩大白名单、吞异常、生成模板、改预期为错误现状来通过。

完成标准：代码、迁移/回退说明、输入输出样例、至少一个反例、实际测试命令与退出码、未完成列表齐全。状态使用 PASS/FAIL/BLOCKED/NOT_RUN/DEGRADED，降级不计完全通过。

## 7. 自动化验收矩阵

使用新建、可控的短篇原创测试语料：校园日常、含明确超自然规则、无超自然规则各一种。每本记录事件节点、人物知情、允许愿望、不可添加事实。固定测试夹具只用于确定性回归，不计真实模型质量通过。

| F02 | 人物怀疑有人跟踪 | 摘要仍保留“怀疑”，不得转为事实 |

## 8. 真实生成与长链路验收

### 8.1 开始前置条件

C00–C10 的必需确定性用例通过，隔离清单齐全后才能运行。需要用户重新授权启动试验；当前停止指令持续有效。模型端点和凭据须当次合法提供，不复用旧凭据。使用队列桥时必须显式固定队列目录，记录 model-source=human_bridge；不作为独立真实模型验收。

### 8.2 两条独立质量跑道

A. 能力较弱模型：至少一个可用弱模型，测试受限上下文、短回答、格式错误恢复。目的为可运行、非死锁与不污染。
B. 目标生产模型：验证正常质量与原书节奏。不得以 A 的降级完成冒充 B 的优质通过。

每条跑道使用 3 本短测试书 × 4 类情境 × 15 回合，共 180 回合。情境：遵循原轨道；主动合理分歧；有效愿望；反复诱导无授权阴谋。相同场景定义和玩家输入脚本在跑道间共享，模型输出不能预先写好。追加四策略兼容短链，每策略至少 5 回合。

每轮读取实际提示词来源与提交结果，保留本地证据。生成者不修改答案迎合检查；评审不以“故事好看”为理由接受无授权事实。语义争议由有原文依据的人工抽检裁定，不能用另一个模型的分数作为唯一裁决。

### 8.3 预先冻结的验收标准

硬标准：跨域泄漏、无授权权威状态变更、有效愿望被静默删除/重复扣次、事务部分提交、无限重试、晚到结果提交均为 0。这里按已确认证据判定，不把自动语义检查的疑似项直接算实锤。

所有请求均在配置总预算加合理调度余量内终结；UI 恢复不依赖重启服务。

正常无故障场景：目标模型有效提交率初始门槛 >=95%；弱模型 >=80%，另报 warning 比例。故意损坏/超时的故障样本单独统计，不混入成功率。门槛是待冻结的验收政策而非已测能力；若弱模型达不到，结论是“不支持该模型”，不能现场降标准或用全失败冒充非死锁通过。

节奏：对每条无明确玩家停留的 15 回合链，按预先列明的事件节点评价，至少 80% 达到预期节点或具有可追溯的授权/玩家因果替代；不能用“文中提到节点”算完成。自主支线不得连续 3 个已提交回合替代当前目标且没有玩家选择或原文依据。该指标只用于离线验收，不作为线上强制模型三轮过关门禁。

原著问答：事实与引用必须有来源，未知允许明确不知道；拒答/不确定比例单列，不能用全部拒答伪装忠实。正常答案覆盖率目标 >=90%，弱模型 >=75%。

愿望覆盖：F04/F06/F07/F09/F24 对应成功路径必须实际覆盖，不能因全部拒绝愿望而达到“零扩张”。

文笔、人物口吻、冗余作为人工软评分报告；不采用某个文风分数自动无限返工。指标必须在真实测试前冻结，修改指标需要新版本、新一轮结果。

## 9. GUI 与并行验收

真实 GUI：上传/打开短测试书 → 阅读原文 → 查看源锚点 → 创建本局 → 三愿码 → 回合/任务 → 本局阅读 → 原著对照 → 访谈 → 保存加载 → 导出 → 失败/取消恢复。补测移动视口、快速切视图、缺锚点和网络断开。

确认来源标签、愿望状态、错误原因可读；所有失败保留用户输入；无一直转圈。截图只保存在开发目录下。

并行分两步：先 2 个隔离实例排除串数据，再 12 实例跨 source/session/branch/request_id 测试。只有独立资源可承载时运行；模型调用使用明确并发上限。不得用单队列人工回答速度衡量产品吞吐。旧大规模全真计划在本计划门禁完成前不恢复。

## 10. 缺陷等级、证据与退出

P0：私有数据泄漏、跨用户/会话写入、不可恢复数据破坏。
P1：有效愿望失效/错误扣次、原著与本局串事实、任务重复结算、持续无法恢复 busy、无授权重大状态提交。
P2：长期节奏偏离、拒答过多、弱模型正常场景可用性不达标、摘要来源丢失但未写权威状态。
P3：口吻、标签、轻微冗余等不影响正确性的体验问题。

每条缺陷保留：版本、场景 ID、模型类别、来源上下文标识、请求 ID、前后 revision、错误分类、调用计数、预算、是否降级、用户可恢复性。禁止把凭据或完整私有原书写到公共报告。

线上有限重试与施工修复循环分开：一个请求达到预算立即终止；一个施工卡连续两轮最小修复仍不通过则暂停该卡，记录差异请求评审，不无限扩大改动。

最终发布门禁：P0/P1 清零；所有确定性必需用例通过；目标模型正常可用性/节奏达标；弱模型支持范围明确；原著、愿望、本局三类事实均有正反例实测；GUI/持久化/隔离通过。任何 BLOCKED/NOT_RUN 不计通过。不能只拿非死锁结果宣布剧情质量验收完成。

## 11. 回退与交付

新语义策略可用默认关闭的显式功能开关逐步验证；三愿码授权记录与来源标签不能因关闭开关丢失。先进行新测试档验证，再决定迁移，不批量重写用户旧档。新字段迁移必须可重复运行，保留旧字段读取兼容与原始备份；不承诺不兼容的旧二进制能直接读新档。

交付物：
1. 契约字段映射与来源/授权优先级说明。
2. C00–C10 逐卡改动、失败测试与回归记录。
3. 迁移、回退、功能开关与预算配置说明。
4. F01–F28 结果和证据索引。
5. 弱模型/生产模型分别统计的真实链路报告。
6. 阅读器 GUI、跨实例、存读档验收报告。
7. 剩余缺陷及支持边界，清楚区分通过、降级、阻塞、未测。

本计划的核心判据：原著约束不会取消合法愿望；合法愿望不会授权无限扩张；质量不足不会造成无限重试；有限失败也不会被冒充为剧情质量通过。
