## 核心概念

### 什么是 Novelborne

Novelborne 是一个由大模型驱动的**互动小说世界模拟器**。与传统聊天机器人不同：

- ✅ **世界有规则**：剧情锚点、任务、角色状态、收束力由代码管理
- ✅ **模型有约束**：场景门禁会拦截不符合规则的内容，要求重写
- ✅ **玩家是穿越者**：你不是旁观者，而是世界中的参与者

### 三大核心机制

#### 1. 原著锚点（Anchor）
- 从原著小说中提取的关键剧情节点
- 确保世界"感觉对劲"，保持原著风格
- 可通过"碎锚"打破，开启原创分支

#### 2. 收束力（Convergence）
- 世界对"改变"的抵抗程度
- 越高，剧情越贴近原著，你的改变越难
- 越低，世界越接受你的改变，但风险和代价增大

#### 3. 场景门禁（Scene Gate）
- 代码层面的质量检查
- 拦截不合理的剧情（过短、格式错误、违反设定）
- 确保世界模拟的稳定性

## 游戏模式

### 基础模式

**特点**：
- 使用作品库中的现成作品或题材碎片
- 轻量级，快速开局
- 适合体验和快速游玩

**限制**：
- 剧情丰度仅前两档
- 部分高级功能不可用

### 强化模式（推荐）

**特点**：
- 上传完整TXT原著小说
- 锚点蒸馏 + 角色卡生成
- 完整功能支持

**优势**：
- 剧情丰度全六档
- 完整的宿敌/碎锚/任务链
- 更高的还原度和沉浸感

## 世界规则系统

### 收束力档位

| 档位 | 名称 | 说明 |
|------|------|------|
| 极高 | 铁轨剧情 | 原著大事件必然发生，你只能改变过程 |
| 较高 | 紧贴原著 | 剧情强力回归原著，改变代价很大 |
| 中等 | 平衡 | 原著与原创的平衡点 |
| 较低 | 蝴蝶效应 | 你的行动容易产生连锁反应 |
| 极低 | 自由创作 | 世界高度接受改变，接近原创小说 |

### 难度系统

| 难度 | 代号 | 说明 |
|------|------|------|
| D1 | 故事模式 | 场景门禁宽松，重在叙事体验 |
| D2 | 简单 | 适度挑战，新手友好 |
| D3 | 标准 | 标准难度，需要策略 |
| D4 | 普通 | 需要较好的规划和决策 |
| D5 | 困难 | 高风险高回报 |
| D6 | 地狱 | 极限挑战，容错率极低 |

### 剧情丰度

控制每回合生成的故事篇幅：

- **500字**：精简叙事，快节奏
- **800字**：标准篇幅
- **1200字**：详细描写
- **1600字**：丰富剧情
- **2000字**：史诗级叙事
- **2500字**：极致细腻（需要强大模型）

## 金手指系统

### 金手指分类

#### 感知类
- **透视眼**：看穿物体、看到隐藏信息
- **读心术**：感知他人想法和情绪
- **危险感知**：提前预警危险

#### 知识类
- **百科全书**：任何领域的知识
- **先知预言**：预知未来片段
- **记忆宫殿**：过目不忘

#### 能力类
- **武力倍增**：战斗力增强
- **魅力光环**：提升社交影响力
- **学习加速**：快速掌握技能

#### 物质类
- **空间戒指**：随身储物空间
- **炼金术**：物质转化
- **召唤系统**：召唤物品或生物

#### 系统类
- **签到系统**：定期获得奖励
- **任务系统**：完成任务获得资源
- **商城系统**：兑换特殊物品

### 金手指设计原则

1. **有作用范围**：不是全能神器
2. **有代价**：使用需要付出成本（能量、冷却、副作用）
3. **有冷却**：不能无限使用
4. **可成长**：可以随剧情升级

### 金手指推荐系统

系统会基于：
- 原著风格
- 主角人设
- 选定的宿敌

自动推荐3-5个适配的金手指。

## 角色系统

### 角色类型

#### 伴侣（Companion）
- 陪同你冒险的同伴
- 需要设置：姓名、技能、背景、参与度(1-10)
- 参与度越高，出场越频繁

#### 女主（Heroine）
- 主要的感情线角色
- 模式选择：
  - **单女主**：专注一条感情线
  - **多女主**：多条感情线并行
  - **后宫**：后宫向发展

#### 宿敌（Nemesis）
- 主要对手和冲突来源
- 类型：
  - 世家少爷（身份碾压）
  - 门派精英（天赋对抗）
  - 朝廷鹰犬（权力斗争）
  - 邪道魔头（理念冲突）
  - 幕后掮客（智谋较量）
  - 自定义

### 角色设计器

**功能**：
- 姓名生成（基于原著风格）
- 技能建议
- 背景故事生成
- 性格特征定义

### 角色库

**内置角色**：
- 从原著中提取的经典角色
- 包含：姓名、性格、技能、关键事件
- 可直接引用到游戏中

## 碎锚系统

### 什么是碎锚

**碎锚（Break Anchor）** = 打破原著剧情锚点，开启原创分支

### 触发条件

1. **积势充足**：通常需要推进10+回合
2. **没有进行中的碎锚**：同时只能有一个碎锚
3. **冷却完成**：上次碎锚后需要冷却

### 碎锚流程

#### 1. Offer（提议）
- 系统生成2-4个碎锚分支选项
- 展示每个选项的预期影响
- 显示所需积势

#### 2. 选择
- **Accept**：接受碎锚，进入新分支
- **Decline**：拒绝碎锚，保留机会

#### 3. 执行
- 打破原著锚点
- 开启原创剧情
- 世界规则相应调整

### 碎锚效果

- ✅ 突破原著限制
- ✅ 创造独特剧情
- ⚠️ 增加不确定性
- ⚠️ 可能触发连锁反应

### API接口

```bash
# 发起碎锚
POST /api/sessions/{session_id}/break-anchor/offer

# 拒绝碎锚
POST /api/sessions/{session_id}/break-anchor/decline

# 接受碎锚
POST /api/sessions/{session_id}/break-anchor/accept
```

## 作弊码系统

### 什么是作弊码

作弊码是开发者提供的特殊指令，用于：
- 调试功能
- 降低难度
- 探索玩法

**重要提示**：作弊码只在 `ask` 端点（问答框）输入有效，在剧情选择等其他输入框中无效。

### 三愿码（WISH）

#### 激活码
```
UUDDLLRRBABAWHOSLOMSTINGNOTALADDIN
```

#### 功能
- 激活"许愿系统"
- 获得**3次**许愿机会
- 每次许愿消耗1次机会

#### 使用方法
1. 在问答框输入激活码
2. 系统提示愿望系统已激活
3. 输入你的愿望（自然语言）
4. 系统会尝试实现愿望

#### 愿望规则

**可以许愿**：
- 获得物品："我希望获得一把神剑"
- 改变状态："我希望掌握御剑术"
- 修改关系："我希望xxx对我好感度提升"
- 改变世界："我希望这个城市进入战时状态"

**不可许愿**（机制护栏）：
- ❌ 修改游戏机制（回合数、难度、收束力）
- ❌ 修改金手指设定
- ❌ 修改任务和积势
- ❌ 直接控制剧情走向

#### 愿望实现

- 系统将愿望写入"铁律设定"
- 优先级**高于剧情**但**低于机制**
- 后续剧情会自然实现愿望
- 可能需要1-2个回合完整体现

#### 示例

```
玩家：UUDDLLRRBABAWHOSLOMSTINGNOTALADDIN
系统：愿望系统已激活，剩余3次许愿机会

玩家：我希望获得一枚能疗伤的丹药
系统：愿望已记录，正在实现...（剩余2次）

[下一回合剧情中会自然出现获得丹药的情节]
```

### 永久通路码（RELAY）

#### 激活码
```
RELINKBACKLOMSTINGSEEYAGOODAFTERNOONGOODEVENINGANDGOODNIGHTBLACKSHEEPWALL
```

#### 功能
- 问答框永久接通主线剧情
- 你在问答框的输入会直接影响剧情
- 不需要选择选项，自由输入行动

#### 使用方法
1. 在问答框输入激活码
2. 系统提示永久通路已激活
3. 后续可以在问答框自由输入行动

#### 效果对比

**未激活永久通路**：
- 问答框只能问问题
- 必须选择A-F选项推进剧情

**激活永久通路后**：
- 问答框输入的行动直接进入主线
- 仍然可以选择选项
- 两种方式并行，更灵活

#### 示例

```
玩家：RELINKBACKLOMSTINGSEEYAGOODAFTERNOONGOODEVENINGANDGOODNIGHTBLACKSHEEPWALL
系统：永久通路已激活

玩家：我悄悄跟踪那个可疑的黑衣人
系统：[生成完整剧情，描述跟踪过程和结果]

玩家：我停下来，观察周围环境
系统：[生成环境描述和新选项]
```

### 作弊码组合使用

两个作弊码可以同时激活：
- 先激活三愿码许愿
- 再激活永久通路自由行动
- 获得最大的自由度

### 作弊码注意事项

1. **作弊码只在问答框有效**
   - 剧情选择框中输入无效
   - 其他输入框中无效

2. **作弊码区分大小写**
   - 必须完全按照格式输入
   - 少一个字母都无效

3. **愿望有机制护栏**
   - 不能破坏游戏规则
   - 不能获得无限资源
   - 系统会剥离不合理部分

4. **永久通路仍受场景门禁约束**
   - 不合理的行动会被拒绝重写
   - 不是"无敌模式"

## 存档系统

### 存档机制

#### 自动存档
- 每回合结束后自动保存
- 保留完整的游戏状态

#### 手动存档
- 任意时刻可以创建存档点
- 支持多个存档槽位

### 存档内容

存档包含：
- ✅ 完整的状态数据（回合、章节、积势）
- ✅ 角色信息和关系
- ✅ 任务进度
- ✅ 金手指状态
- ✅ 历史对话记录
- ✅ 作弊码激活状态

### 读档功能

#### 独立读档
- 从任意存档恢复
- 不影响原存档

#### 分支实验
- 从存档点创建多个分支
- 探索不同的可能性

### 小说导出

#### 功能
- 将游戏过程导出为完整小说
- 格式：TXT / Markdown
- 包含完整剧情和选择记录

#### 导出内容
- 按回合组织的章节
- 完整的对话和描写
- 选择节点标注（可选）

## API接口

### 核心端点

#### 健康检查
```bash
GET /api/health
# 返回：{"ok": true, "service": "fate-engine-api", "version": "2.1.1"}
```

#### 会话管理
```bash
# 创建会话并开局
POST /api/sessions/start
{
  "session_id": "string",
  "provider": "zhipu",
  "api_key": "string",
  "model": "string",
  "mode": "强化模式",
  "novel_upload_id": "string",
  ...
}

# 获取会话状态
GET /api/sessions/{session_id}/state

# 发送行动
POST /api/sessions/send
{
  "session_id": "string",
  "message": "选择A"
}
```

#### 文件上传
```bash
# 上传TXT原著
POST /api/uploads
Content-Type: multipart/form-data
- session_id: string
- kind: "novel"
- file: File
```

#### 碎锚
```bash
# 发起碎锚
POST /api/sessions/{session_id}/break-anchor/offer

# 拒绝碎锚
POST /api/sessions/{session_id}/break-anchor/decline

# 接受碎锚
POST /api/sessions/{session_id}/break-anchor/accept
```

#### 作弊码（通过ask端点）
```bash
# 问答/作弊码
POST /api/sessions/{session_id}/ask
{
  "question": "UUDDLLRRBABAWHOSLOMSTINGNOTALADDIN"

```

#### 存档

```bash
POST /api/sessions/{session_id}/save

  "slot_name": "string"
```

```bash

{
  "provider": "string",
  "api_key": "string",
  "model": "string"
}

# 金手指推荐

{
  "context": "string"
}

# 角色设计
POST /api/character-designer/suggest
{
  "role": "companion",
  "context": "string"

# 原著章节列表
GET /api/chapters?work_id=xxx

# 原著内容阅读
GET /api/read-chapter?work_id=xxx&chapter=1
```

## 常见问题

### Q: API Key 会被保存到本地吗？
**A**: 不会。API Key 只在内存中持有，重启后需要重新输入。

### Q: 可以导入其他小说吗？
**A**: 可以。强化模式支持上传任意TXT格式的小说。

### Q: 碎锚会消耗积势吗？
**A**: 正常碎锚会消耗积势，但使用永久通路码激活的特权碎锚不消耗。

### Q: 作弊码影响存档吗？
**A**: 作弊码激活状态会保存在存档中。读档后作弊码状态恢复。

### Q: 可以在移动设备上玩吗？
**A**: 可以。前端响应式设计，支持平板和手机（推荐平板以获得更好体验）。

### Q: 支持多人游戏吗？
**A**: 目前不支持。每个会话独立，但可以通过导出小说分享剧情。
