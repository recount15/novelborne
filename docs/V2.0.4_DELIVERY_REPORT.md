## 二、技术架构详解

### 2.1 Agent_refill 核心模式

**设计原则**：批改-重填循环 + Keep-best选择

```python
# 通用流程（应用于聊天生成、任务判定）
current = model_call(initial_prompt)
best = current
best_errors = grader.grade(current)

for _ in range(attempts):  # attempts ≤ 2
    if not current_errors: break
    
    refill_prompt = grader.build_refill_prompt(current_errors)
    candidate = model_call(refill_prompt)
    candidate_errors = grader.grade(candidate)
    
    # Keep-best：选择错误更少的版本
    if len(candidate_errors) < len(best_errors):
        best = candidate
        best_errors = candidate_errors
    current = candidate

return best
```

**Token 消耗权衡**：
- 单次生成 → agent_refill（2次尝试）：约 +33% token消耗
- 用户明确表示可接受："我可以接受额外的token消耗"
- 质量提升显著：6维度验证 + 角色voice一致性

#### Layer 2: 批改器（chat_grader.py）

**6维度质量检查**：

```python
def grade_chat_reply(character, reply) -> list[str]:
    """返回中文错误清单（空列表=通过）"""
    errors = []
    
    # 1. 字数窗口（50-150字）
    if len(reply) < 50:
        errors.append(f"字数过少（{len(reply)}字，应≥50字）")
    elif len(reply) > 150:
        errors.append(f"字数过多（{len(reply)}字，应≤150字）")
    
    # 2. 脚手架残留
    scaffolds = ["【", "】", "##", "```", "角色：", "回复："]
    if any(s in reply for s in scaffolds):
        errors.append("包含脚手架格式残留")
    
    # 3. JSON 格式残留
    json_markers = ["{", "}", '"reply":', '"character":']
    if any(m in reply for m in json_markers):
        errors.append("包含 JSON 格式残留")
    
    # 4. 元叙述
    meta_phrases = ["作为", "我作为", "我是一个", "根据设定"]
    if any(p in reply for p in meta_phrases):
        errors.append("包含元叙述")
    
    # 5. 禁止行为
    if any(word in reply for word in ["给你", "送你", "这个给你"]):
        errors.append("禁止行为：给予物品")
    if any(word in reply for word in ["其实", "真相是", "秘密"]):
        errors.append("禁止行为：剧透锚点")
    if any(word in reply for word in ["我得走了", "该离开了"]):
        errors.append("禁止行为：角色离场")
    
    # 6. Voice 一致性
    voice = character.get("voice", "")
    if "冷淡" in voice or "严肃" in voice:
        if any(excited in reply for excited in ["！", "哈哈", "太棒了"]):
            errors.append(f"Voice 不一致：设定为「{voice}」但回复过于热情")
    elif "热情" in voice or "活泼" in voice:
        if all(formal in reply for formal in ["您", "敬请"]):
            errors.append(f"Voice 不一致：设定为「{voice}」但回复过于正式")
    
    return errors
```

// 根据 active_members 刷新可聊天角色列表
async function refreshChatRoster(): Promise<void> {
  if (!sessionId.value || !inGame.value) {
    chatRoster.value = []
    return
  }
  const roster = await getChatRoster(sessionId.value)
  chatRoster.value = roster
  
  // 当前选中角色若已离场，清空选择
  if (selectedCharacter.value && 
      !roster.some(r => r.name === selectedCharacter.value)) {
    selectedCharacter.value = ''
    chatMessages.value = []
  }
}

// 发送聊天消息
async function sendChat(): Promise<void> {
  const message = chatInput.value.trim()
  if (!message || !selectedCharacter.value) return
  
  chatBusy.value = true
  try {
    const result = await sendChatMessage(
      sessionId.value, 
      selectedCharacter.value, 
      message
    )
    chatMessages.value.push({ 
      player: message, 
      reply: result.reply 
    })
    chatInput.value = ''
  } finally {
    chatBusy.value = false
  }
}

// 监听 active_members 变化
watch(() => state.value.active_members, () => {
  void refreshChatRoster()
}, { deep: true })
```

## 四、状态隔离保证

### 4.1 隔离设计原则

**铁律**：闲聊系统**只读剧情状态，单向写入 side_chats**

```python
# chat_service.py 读取（只读）
def generate_reply(character_name, message, state, ...):
    # ✅ 允许读取
    character = _find_character(state["active_members"], character_name)
    scene_excerpt = state.get("context_summary", "")[-200:]
    recent_summary = state.get("recent_summary", "")
    protagonist_state = _extract_protagonist_facts(state)
    
    # ❌ 绝不写入剧情关键字段
    # state["history"] = ...  # 禁止
    # state["state_memory"] = ...  # 禁止
    # state["quest"] = ...  # 禁止
    
    # ✅ 仅写入隔离字段
    if "side_chats" not in state:
        state["side_chats"] = {}
    if character_name not in state["side_chats"]:
        state["side_chats"][character_name] = []
    state["side_chats"][character_name].append({
        "player": message,
        "reply": reply,
        "timestamp": time.time()
    })
```

### 4.2 上下文单向流动

```
┌─────────────────┐
│  Narrative      │  主剧情引擎
│  Engine         │
└────────┬────────┘
         │ 单向读取
         ↓
┌─────────────────┐
│  Chat Service   │  闲聊服务
│  (side_chats)   │
└─────────────────┘
```

**验证点**：
- `run_turn` 与 `ModularContext` 永不读 `side_chats`
- 聊天不消耗回合，不触发 `settle_round`
- 聊天不影响 `convergence`、`ripple`、`anchors`

        if any(word in reply for word in cold_formal):

    if any(warm in voice for warm in ["温暖", "热情", "活泼"]):

### 8.4 叙事流畅度6层检测系统（narrative_flow_grader.py）

#### 设计原则

**核心理念**："不光保证性能指标，切切实实作用到用户体验提升"

1. **从表层到深层**：6层递进检测，浅层问题不掩盖深层问题
2. **每层独立评分**：分数反映真实质量，避免单一综合分的过拟合
3. **读者影响描述**：每个issue说明"读者会感到X"，不是抽象指标
4. **具体改进建议**：issue包含actionable修复方向，不是泛泛评价
5. **加权合成**：沉浸感25%权重最高，体现"真实体验优先"

#### 6层架构

```python
# 最低要求：≥100字 且 ≥3句，否则无法可靠评估
MIN_NARRATIVE_LENGTH = 100
MIN_SENTENCE_COUNT = 3

def grade_narrative_flow(narrative: str, context: dict | None = None) -> dict:
    """6层检测系统，每层独立评分后加权合成
    
    Returns:
        {
            "score": 0-100 综合分数,
            "issues": ["[层级标签] 问题描述 + 读者感受 + 改进建议"],
            "layer_scores": {
                "surface": 表层分数 (15%),
                "structure": 结构分数 (20%),
                "immersion": 沉浸感分数 (25% - highest weight),
                "language": 语言质量分数 (15%),
                "tension": 叙事张力分数 (15%),
                "readability": 可读性分数 (10%),
            },
            "metrics": {详细指标}
        }
    """
```

#### 第1层：表层检测（Surface，权重15%）

**检测项**：
1. **句长变化**：标准差<5 → 节奏单调
2. **用词重复**：100字内同一2字词出现≥3次 → 啰嗦
3. **句式重复**：连续3句相同开头 → 疲劳

**评分**：`100 - len(surface_issues) * 10`

**Issue示例**：
```
[节奏单调] 句长变化过小（标准差 3.2，应≥5），读者易感疲劳。建议长短句交错，短句制造紧张，长句营造氛围
[用词重复] 「房间」在100字内出现3次，读者会感到啰嗦。建议用同义词替换，或调整句子结构避免重复
```

#### 第2层：结构检测（Structure，权重20%）

**检测项**：
1. **段落衔接突兀**：「突然/忽然/猛然」密集出现
2. **时态混乱**：混用「曾经/过去」与「正在/现在」，无转换标记
3. **逻辑断层**：转折与因果混用，结构词不配对（首先...无其次）

**评分**：`100 - len(structure_issues) * 15`

**Issue示例**：
```
[段落衔接突兀] 「突然」在短文内出现4次，读者会感到事件推进生硬。建议用铺垫代替突转，如环境细节渐变或角色察觉过程
[时态混乱] 正文混用过去时与现在时，缺少明确转换标记。读者会困惑「这是回忆还是当前发生」。建议明确时间线，或用「想起/恍惚间」等词引导回忆
```

#### 第3层：沉浸感检测（Immersion，权重25%最高）

**检测项**：
1. **元叙述泄露**：「正如我们所见/如前所述/本章」
2. **视角混乱**：第一人称与第三人称混用
3. **情感钝化**：过多「感到/觉得/很XX」直接告知，缺少细节展示

**评分**：`100 - len(immersion_issues) * 12`

**Issue示例**：
```
[元叙述泄露] 出现「正如我们所见」，读者会跳出故事世界。建议删除元叙述，直接描写场景
[情感钝化] 过多直接告知情感「感到/觉得/很XX」(2次/3句=67%)，读者无法共鸣。建议用具体细节展示：颤抖的手，急促的呼吸，紧咬的牙关
```

**为什么权重最高**：沉浸感直接决定"读者是否身临其境"，是用户体验的核心。

#### 第4层：语言质量检测（Language，权重15%）

**检测项**：
1. **口语化残留**：「嗯/啊/那个/这个」过多
2. **陈词滥调**：「众所周知/不言而喻/理所当然」
3. **信息密度**：实词（名词/动词/形容词）占比<40%

**评分**：`100 - len(language_issues) * 8`

**Issue示例**：
```
[口语化残留] 过多使用口语标记「嗯/啊/那个」(3次)，书面叙述应更正式。读者会感到文本不够精炼。建议改用描述性语言
[陈词滥调] 使用「众所周知」等套话，读者会感到缺乏新意。建议用具体事实替代抽象评价
```

#### 第5层：叙事张力检测（Tension，权重15%）

**检测项**：
1. **冲突缺失**：无动作/对话/张力词，平淡无聊
2. **节奏失控**：长句占比>80%沉闷，短句占比>80%支离破碎
3. **描写空洞**：感官词密度<1.0/句，无法身临其境

**评分**：`100 - len(tension_issues) * 10`

**Issue示例**：
```
[冲突缺失] 缺少动作、对话或张力词，叙述过于平淡。读者会感到无聊。建议加入角色行动、对话冲突、或营造紧张气氛
[描写空洞] 感官细节不足（平均每句0.6个感官词），读者无法身临其境。建议增加视觉、听觉、触觉细节
```

#### 第6层：可读性检测（Readability，权重10%）

**检测项**：
1. **雾凇指数**：`0.4 * (平均句长 + 难词率*100)` > 30 → 过难
2. **情感共鸣度**：情感词密度<0.5/句 → 难以共鸣

**评分**：`100 - len(readability_issues) * 8`

**Issue示例**：
```
[可读性差] 雾凇指数31.2>30，句子过长或用词过难。普通读者需多次阅读才能理解。建议拆分长句，简化用词
[情感共鸣弱] 情感词密度低（每句0.3个），读者难以产生情感共鸣。建议增加情感描写，让读者与角色同喜同悲
```

#### 加权综合评分

```python

### 8.6 真实体验提升验证

#### 避免过拟合的设计
1. **分层独立评分**：不能靠单一维度刷高分，必须所有层都良好
2. **读者影响描述**：每个issue说明真实阅读感受，不是抽象分数
3. **具体改进建议**：actionable修复方向，不是"提高质量"之类空话
4. **加权反映优先级**：沉浸感25%最高，体现"体验>指标"

#### 对比：旧版 vs 新版

| 维度 | 旧版（单一分数） | 新版（6层检测） |
|------|---------------|---------------|
| **评分粒度** | 单一综合分 | 6层独立分+加权合成 |
| **问题定位** | "质量78分" | "[沉浸感] 元叙述泄露，读者会跳出故事" |
| **改进指导** | "提高质量" | "删除「正如我们所见」，直接描写场景" |
| **过拟合风险** | 高（刷某个指标即可） | 低（必须6层都良好） |
| **真实体验** | 不明确 | 每个issue说明读者感受 |
